# CLAUDE.md

Guidance for Claude Code and any contributor working in this repository.

Client Task Tracker is a Google Apps Script web app bound to a Google Sheet. The front end is
React + TypeScript bundled by Vite into one HTML file; the back end is Apps Script written in
TypeScript and bundled with esbuild.

## Commands

| Task                                                              | Command                                               |
| ----------------------------------------------------------------- | ----------------------------------------------------- |
| Install                                                           | `npm ci`                                              |
| Local dev (mock server, fake data)                                | `npm run dev`                                         |
| Unit and component tests                                          | `npm test` (watch: `npm run test:watch`)              |
| Lint                                                              | `npm run lint`                                        |
| Type check                                                        | `npm run typecheck`                                   |
| Format                                                            | `npm run format` (check only: `npm run format:check`) |
| Build (`dist/index.html`, `dist/Code.js`, `dist/appsscript.json`) | `npm run build`                                       |
| Everything CI runs                                                | `npm run check`                                       |
| Push to Apps Script                                               | `npm run push` (builds, then `clasp push`)            |

### Deploy

1. `npx clasp login` once, then copy `.clasp.example.json` to `.clasp.json` and set `scriptId`
   (or run `npx clasp create --type sheets --rootDir dist`). `.clasp.json` is git-ignored.
2. `npm run push`.
3. First time only: in the Apps Script editor run `setup` once.
4. Apps Script editor: Deploy > Manage deployments > Edit > New version, so the live URL stays
   the same. (First deploy: Deploy > New deployment > Web app, execute as Me, access Anyone with a
   Google account.)

## Layout

| Path                       | Responsibility                                                             |
| -------------------------- | -------------------------------------------------------------------------- |
| `src/shared/`              | Types, Zod schemas and pure business rules, used by client and server      |
| `src/server/main.ts`       | `doGet()`: access check, then serves the built page                        |
| `src/server/auth.ts`       | Signed-in email and allowlist check                                        |
| `src/server/api.ts`        | Functions the page calls; every one checks access first                    |
| `src/server/repository.ts` | Generic read, insert, update and archive for any tab, by header name       |
| `src/server/setup.ts`      | `setup()`: creates missing tabs, headers and default settings              |
| `src/client/`              | React app: `features/`, `components/`, `lib/api.ts` (typed server wrapper) |
| `src/client/mocks/`        | Fake server and sample data for local development and tests                |

## Engineering principles

### Code design

- TypeScript in strict mode; no `any`, no unchecked type casts.
- Keep business rules as pure functions in `src/shared`, separate from Sheets I/O and React, so
  they are easy to test.
- One responsibility per module and component; split any file past about 200 lines.
- Validate every input on the server with the shared Zod schemas, even if the client already did.
- Every server function returns `{ ok, data, error }`; no silent `catch` blocks, and errors shown
  to the user are plain language.
- Clear names over comments; comments explain why, not what. No dead or commented-out code.

### Security and privacy

- Check the allowlist on every server call, not only when the page loads.
- Least-privilege OAuth scopes (`spreadsheets.currentonly` plus the user email); no secrets, IDs or
  emails in code. Per-copy values live in the `Settings` tab or Script Properties.
- Render user text safely (React escaping, no `dangerouslySetInnerHTML`); allow only `http` and
  `https` links.
- Never accept, store or display passwords.

### Data

- Columns are looked up by header name, not position, so users can reorder or add columns.
- Records link by ID (UUIDs generated by the script), never by name.
- Dates are stored as real sheet dates in ISO format; amounts as plain numbers with a separate
  currency column.
- Records are archived, not deleted. Calculated states are never stored.

### Performance

- Read each tab once per request with `getValues()` and write in batches; never loop cell by cell.
- Use `LockService` around writes.
- Keep the bundle small: ask before adding a dependency and prefer the platform or existing
  libraries.

### User experience

- Accessible by default: semantic HTML, labelled inputs, keyboard navigation, WCAG AA contrast.
- Every screen has loading, empty and error states, and works on a phone width (375 px).
- Components use design tokens (CSS variables mapped into Tailwind), never raw hex values. The one
  exception is user-chosen status colours, which are data.

### Testing and workflow

- Unit tests for every business rule (contract and subscription state, cash-flow totals,
  validation) and key components.
- Work one phase at a time; each feature is a small branch and pull request that passes lint,
  typecheck, tests and build.
- Conventional commit messages; update `README.md` and `CHANGELOG.md` with each user-facing change.
- When requirements are unclear, stop and ask rather than guess.

## Decisions already made

- Web app runs as the deploying user, access "Anyone with a Google account". Apps Script often
  returns an empty email for personal Gmail users other than the owner, so allowlisted emails
  outside the owner's Workspace domain may be denied. An empty email is always denied.
- `setup()` adds the email of whoever runs it to the allowlist (without duplicates).
- Task statuses are stored as JSON in the `Task statuses` setting; the `Tasks` tab stores the
  status name. Renaming a status rewrites matching task rows in one batch. Status colours are free
  hex values; pill text colour is derived to meet contrast.
- Any status can change to any other. Moving into a done status sets `Delivered on` to today;
  moving out clears it.
- "This week" means today plus the next 6 days, in the spreadsheet's time zone.
- Tasks are not deleted or archived in v1. Clients can be archived and unarchived.
- One `Expiry warning days` setting drives both contract "Expiring soon" and subscription
  "Renewing soon". An end or renewal date of today still counts as soon; it is Expired or Overdue
  from the next day. Window filters include the boundary day.
- A contract is Renewed only when the Renew button created its replacement (`Renewed by ID`).
  Renew pre-fills: start the day after the old end, same length (whole months when the old
  period was whole months). Contracts are never deleted; ending early means editing the end date.
- Auto-renew subscriptions still show Overdue after their date until Mark renewed is used.
- Subscriptions keep a `Billing day` so monthly renewals return to the original day
  (31 Jan → 28 Feb → 31 Mar), and a `Rebill due` date that shows "Charge client" until cleared.
- Currencies come from the `Currencies` setting, with the default currency always first.
- The `Transactions` tab stores Type (Inflow/Outflow) plus a positive Amount. Mark renewed can log
  one Outflow in category `Subscriptions`.
- Cash flow totals and the 6-month chart show one currency at a time (currency switch, default
  first) and never add currencies together. Undated entries count in All time and No date views,
  never in a month. Voided entries (`Voided` column) stay in the sheet but are left out of totals.
- CSV import runs in the browser first (preview of rows, skipped rows with reasons, clients to be
  created), then the server validates every row again, skips duplicates (same date, type, amount
  and description), creates missing clients by name and writes everything in one batch. Headers
  are matched by name (see `src/shared/importColumns.ts`); dates are read day first.
- Contract payments are logged by hand; the entry form can pre-fill from a contract.
- Categories are suggestions kept in the `Categories` setting; entries may use any category.
